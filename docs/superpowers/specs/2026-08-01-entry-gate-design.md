# 사이트 입장 게이트 — 설계 문서

작성일: 2026-08-01

## 1. 목표

시간표를 인터넷에 올리면 주소를 아는 누구나 동아리원들의 일정을 들여다볼 수 있다.
사이트 앞에 **입장 비밀번호** 한 겹을 두어 동아리원만 들어오게 한다.

첫 화면은 소개 문구와 비밀번호 칸 하나뿐이다. 관리자는 그 문구와 입장 비밀번호를
사이트 안에서 고칠 수 있다.

### 만드는 것

- 입장 비밀번호를 넣어야 열리는 첫 화면 (제목 · 설명 · 입력칸)
- **모든 `/api/*` 요청 차단** — 주소를 알아도 비밀번호 없이는 데이터를 못 받는다
- 관리자 모드에서 입장 비밀번호와 첫 화면 문구 수정

### 만들지 않는 것 (YAGNI)

- 사람마다 다른 입장 비밀번호 — 동아리가 함께 쓰는 하나면 된다
- 초대 링크, 이메일 인증, 가입 승인
- 입장 기록(누가 언제 들어왔는지)
- 마크다운 렌더링 — 제목과 여러 줄 설명이면 충분하다

## 2. 데이터

새 테이블 없이 기존 `settings` 테이블에 키 셋을 더한다.

| 키 | 내용 |
|---|---|
| `gate_password_hash` | 입장 비밀번호의 bcrypt 해시 |
| `gate_title` | 첫 화면 제목 (한 줄) |
| `gate_intro` | 첫 화면 설명 (여러 줄) |

최초 실행 때 환경변수 `GATE_PASSWORD`로 해시를 세운다. `ADMIN_PASSWORD`와 같이
**없으면 서버가 시작을 거부**한다 — 게이트 없이 배포되는 사고를 막는다.

제목과 설명은 처음에 이 값으로 시작하고, 관리자가 사이트에서 고친다.

```
제목: 동아리 주간 시간표
설명: 동아리원만 볼 수 있습니다. 받은 비밀번호를 넣어 주세요.
```

`ADMIN_PASSWORD`가 매번 관리자 해시를 덮어쓰는 것과 달리, **`GATE_PASSWORD`는
비어 있을 때만 세운다.** 관리자가 사이트에서 바꾼 비밀번호가 서버를 다시 띄울 때마다
환경변수 값으로 되돌아가면 안 되기 때문이다.

## 3. 차단

### 미들웨어 한 겹

`/api/` 로 시작하는 요청은 `X-Gate-Password` 헤더를 요구한다. 없거나 틀리면
`401` 과 함께 `X-Gate: required` 헤더를 돌려준다. 프론트는 이 헤더를 보고
첫 화면으로 돌아간다 — 개인 비밀번호가 틀린 `401` 과 구별해야 한다.

예외는 둘뿐이다.

- `GET /api/gate` — 첫 화면을 그리려면 제목과 설명이 필요하다
- `POST /api/gate/verify` — 입장 비밀번호를 확인하는 곳

정적 파일(`/`, `/assets/*`)은 막지 않는다. 화면 껍데기는 공개해도 무방하고,
막으면 첫 화면 자체를 띄울 수 없다.

### 검증 결과를 재사용한다

bcrypt 검증은 100ms 안팎이 걸린다. 화면이 15초마다 폴링하므로 매번 다시 계산하면
낭비다. **통과한 비밀번호의 SHA-256 만 메모리에 담아 두고** 다음부터는 건너뛴다.

- 평문은 남기지 않는다
- 관리자가 입장 비밀번호를 바꾸면 이 목록을 비운다 — 모두 다시 입력한다
- 서버를 다시 띄우면 비므로 첫 요청 한 번만 느리다

### 시도 제한은 확인 창구에만

`POST /api/gate/verify` 에만 시도 제한을 건다(같은 IP, 10회 실패 시 10분).

미들웨어에서까지 실패를 세면 안 된다. 관리자가 비밀번호를 바꾼 걸 모르고 화면을
켜 둔 사람은 15초마다 실패하게 되는데, 그러면 2분 반 만에 자기도 모르게 잠긴다.
미들웨어는 통과와 거부만 판정하고, 잠금은 사람이 직접 입력한 경우에만 센다.

## 4. API

```
GET /api/gate                                    [게이트 없이]
→ { title: str, intro: str }

POST /api/gate/verify                            [게이트 없이]
body: { password: str }
→ 200 { ok: true } | 401 { detail } | 429 { detail }

PATCH /api/gate                                  [관리자]
body: { title?: str, intro?: str, password?: str }
→ 200 { title, intro }
```

- `title` 1~40자, `intro` 0~500자
- `password` 는 4자 이상. 개인 비밀번호처럼 숫자 4자리로 묶지 않는다 —
  동아리 전체가 공유하고 오래 쓰는 값이라 길게 정할 수 있어야 한다
- `PATCH` 로 비밀번호를 바꾸면 검증 캐시를 비운다

## 5. 화면

### 첫 화면

```
┌────────────────────────────────────────┐
│                                        │
│         4thIS 동아리 시간표             │  ← gate_title
│                                        │
│   동아리원만 볼 수 있습니다.            │  ← gate_intro
│   받은 비밀번호를 넣어 주세요.          │     (줄바꿈 그대로 표시)
│                                        │
│   ┌──────────────────┐  ┌──────────┐  │
│   │ 비밀번호          │  │ 들어가기  │  │
│   └──────────────────┘  └──────────┘  │
│                                        │
└────────────────────────────────────────┘
```

가운데 한 덩어리. 시간표 화면과 같은 잉크·종이 색을 쓰되, 여기서는 표가 없으므로
여백을 넉넉히 두고 제목을 크게 세운다.

통과하면 지금 시간표 화면이 그대로 나온다. 입장 비밀번호는 이미 쓰고 있는
`localStorage` 키(`club-schedule`)에 `gatePassword` 로 함께 담는다. 선택한 이름
목록·색 기준과 같은 자리다. 다음부터 이 화면을 건너뛴다.

여기만 비밀번호를 저장한다. 개인 4자리와 관리자 비밀번호는 여전히 남기지 않는다.

### 흐름

1. 앱이 뜨면 `GET /api/gate` 로 제목·설명을 받아 둔다
2. 브라우저에 저장된 입장 비밀번호가 있으면 그대로 `GET /api/board` 를 시도한다
3. `401` + `X-Gate: required` 가 오면 첫 화면을 띄운다
4. 통과하면 저장하고 시간표로 들어간다

저장된 비밀번호로 바로 시도하므로, 맞으면 첫 화면이 깜빡이지 않는다.

### 관리자 수정

관리자 모드에서 **입장 설정** 버튼이 하나 는다. 카테고리 편집기와 같은 다이얼로그다.

| 칸 | 내용 |
|---|---|
| 제목 | 한 줄 |
| 설명 | 여러 줄 |
| 새 입장 비밀번호 | 바꿀 때만 채운다 |

비밀번호 칸을 채우면 저장 버튼 위에 경고가 뜬다 — **"바꾸면 모든 동아리원이 다시
입력해야 합니다."** 실수로 바꿔 단체 문의를 받는 일을 막는다.

## 6. 비밀번호 세 개

| 비밀번호 | 무엇을 여는가 | 기억 |
|---|---|---|
| **입장** | 사이트 자체 | 브라우저에 계속 |
| **개인 4자리** | 내 일정 고치기 | 안 함 — 수정할 때마다 |
| **관리자** | 전부 고치기 · 입장 설정 | 안 함 — 새로고침하면 풀림 |

입장 비밀번호만 기억하는 이유는 역할이 다르기 때문이다. 이건 "누구인지"가 아니라
"들어와도 되는 사람인지"를 묻는다. 매번 물으면 쓰기만 번거롭고 얻는 게 없다.

## 7. 에러 처리

| 상황 | 응답 | 화면 |
|---|---|---|
| 입장 비밀번호 없음/틀림 (미들웨어) | 401 + `X-Gate: required` | 첫 화면으로 돌아감 |
| 첫 화면에서 틀림 | 401 | "비밀번호가 맞지 않습니다" |
| 시도 초과 | 429 | "10분 후 다시 시도해 주세요" |
| 관리자 아닌데 `PATCH /api/gate` | 403 | "관리자만 할 수 있습니다" |
| 제목 비어 있음 | 422 | "제목을 넣어 주세요" |
| 새 비밀번호가 4자 미만 | 422 | "4자 이상으로 정해 주세요" |

## 8. 파일

새로 만드는 것:

```
backend/app/gate.py                     검증·캐시·설정 읽기 쓰기
backend/app/routers/gate.py             GET · POST · PATCH /api/gate
backend/tests/test_gate.py              차단·통과·시도 제한·권한
frontend/src/components/GateScreen.vue  첫 화면
frontend/src/components/GateEditor.vue  관리자 수정 다이얼로그
```

고치는 것:

```
backend/app/db.py          gate 기본값 시드
backend/app/config.py      GATE_PASSWORD 읽기
backend/app/main.py        미들웨어 등록, 라우터 등록
frontend/src/api/client.ts X-Gate-Password 부착, X-Gate 감지
frontend/src/stores/board.ts  게이트 상태와 저장
frontend/src/App.vue       통과 전후 분기, 입장 설정 버튼
```

`gate.py` 는 검증과 캐시만 안다. 라우터는 HTTP 만 안다. 미들웨어는 통과 여부만
묻는다. 셋을 갈라 두면 캐시 방식을 바꿔도 라우터가 흔들리지 않는다.

## 9. 테스트

### 백엔드 (pytest)

- 헤더 없이 `GET /api/board` → 401, 응답에 `X-Gate: required`
- 틀린 입장 비밀번호 → 401
- 맞는 입장 비밀번호 → 200
- `GET /api/gate` 는 헤더 없이 200, 제목·설명을 준다
- `POST /api/gate/verify` 성공·실패·10회 후 429
- 미들웨어 거부는 시도 제한을 올리지 않는다 (스무 번 거부당해도 `verify` 가 잠기지 않음)
- `PATCH /api/gate` 는 관리자만, 그 밖에는 403
- 비밀번호를 바꾸면 옛 비밀번호로 오던 요청이 401 이 된다
- 제목·설명 변경이 `GET /api/gate` 에 반영된다
- 빈 제목·짧은 비밀번호는 422

기존 테스트 146개는 게이트 헤더를 붙이도록 `conftest.py` 픽스처 한 곳만 고친다.

### 프론트 (Vitest)

- 게이트 비밀번호가 브라우저에 저장되고 복원된다
- `401` + `X-Gate` 는 게이트 오류로, 그냥 `401` 은 보통 오류로 갈린다

## 10. 배포

Dockerfile 은 그대로고 환경변수만 하나 는다.

| 변수 | 설명 |
|---|---|
| `ADMIN_PASSWORD` | 관리자 비밀번호 (매번 덮어씀) |
| `GATE_PASSWORD` | 입장 비밀번호 **최초 1회만** 세움 |
| `DB_PATH` | SQLite 파일 경로 |

Railway 기준 절차를 README 에 적는다 — 저장소 연결, 환경변수 셋, `/data` 볼륨.
SQLite 파일이 볼륨에 있어야 다시 배포해도 데이터가 남는다.
