# 동아리 주간 시간표 공유 웹 — 설계 문서

작성일: 2026-07-31

## 1. 목표

동아리원들이 각자 접속해 **매주 반복되는 고정 일정**(수업·알바·강의)을 등록하고, 여러 명의 시간표를 엑셀형 격자에 나란히 놓고 비교하는 웹 애플리케이션.

### 만드는 것

- 가로 월~일, 세로 06:00~24:00(30분 단위) 격자 시간표
- 이름 선택(다중) 시 각 요일이 선택된 사람 수만큼 열로 쪼개져 나란히 표시
- 이름·카테고리(학년) 관리, 관리자의 드래그로 순서 및 소속 변경
- 계정 없이 4자리 숫자 비밀번호로 본인 일정 보호, 관리자 비밀번호로 전체 편집

### 만들지 않는 것 (YAGNI)

- 로그인/회원가입/이메일 인증
- **달력 개념 일체** — 날짜, 월, 주차, 연도, 학기, 공휴일. 화면 어디에도 날짜가 뜨지 않는다
- 1회성 일정, 특정 날짜에만 있는 일정
- 격주·월 1회 같은 반복 규칙. 모든 일정은 예외 없이 매주 반복
- 알림, 외부 캘린더 연동, 공강 자동 추천

이 앱이 다루는 것은 **"어느 요일 몇 시부터 몇 시까지 무슨 일정"** 이라는 정보 하나뿐이다. 시간표는 특정 주를 가리키지 않는, 반복되는 한 주의 틀이다.

## 2. 용어

| 용어 | 의미 |
|---|---|
| 카테고리 | 이름을 묶는 그룹. 기본값 "1학년", "2학년", "3학년" |
| 멤버 | 시간표를 가진 사람 하나. 이름 + 4자리 비밀번호 |
| 일정 | 특정 멤버의 특정 요일 시간 구간. 매주 반복 |
| 슬롯 | 30분 단위 시간 칸. `0` = 06:00, `35` = 23:30 |

## 3. 전체 구조

```
[브라우저: Vue 3 + Vite + TypeScript]
        │ HTTP (JSON)
        ▼
[FastAPI]  ── 정적 파일(빌드된 Vue) 서빙도 겸함
        │
        ▼

```

단일 프로세스 배포. 프론트를 빌드해 FastAPI가 서빙하므로 배포 대상은 컨테이너 하나뿐이다.

## 4. 시간 슬롯 모델

06:00~24:00을 30분으로 자르면 36칸이다.

```
slot = (hour - 6) * 2 + (minute >= 30 ? 1 : 0)
```

- `start_slot`: 0 ~ 35 (포함)
- `end_slot`: 1 ~ 36 (**미포함**, exclusive)
- 예) 09:00~10:30 → `start_slot=6, end_slot=9`
- 항상 `start_slot < end_slot`

시간을 정수로 다루므로 겹침 검사가 `a.start < b.end && b.start < a.end` 한 줄로 끝나고, 격자 렌더링은 CSS Grid의 `grid-row` 값으로 직결된다.

## 5. 데이터 모델

```sql
CREATE TABLE categories (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT    NOT NULL UNIQUE,
    sort_order  INTEGER NOT NULL
);

CREATE TABLE members (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    name          TEXT    NOT NULL UNIQUE,
    category_id   INTEGER NOT NULL REFERENCES categories(id),
    password_hash TEXT    NOT NULL,
    sort_order    INTEGER NOT NULL
);

CREATE TABLE schedules (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    member_id   INTEGER NOT NULL REFERENCES members(id) ON DELETE CASCADE,
    day_of_week INTEGER NOT NULL CHECK (day_of_week BETWEEN 0 AND 6),
    start_slot  INTEGER NOT NULL CHECK (start_slot BETWEEN 0 AND 35),
    end_slot    INTEGER NOT NULL CHECK (end_slot   BETWEEN 1 AND 36),
    title       TEXT    NOT NULL,
    color       TEXT    NOT NULL,
    CHECK (start_slot < end_slot)
);
CREATE INDEX idx_schedules_member_day ON schedules(member_id, day_of_week);

CREATE TABLE settings (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
-- key = 'admin_password_hash'
```

- `day_of_week`: 0 = 월요일 … 6 = 일요일. 날짜 컬럼은 어디에도 없다
- `sort_order`: 카테고리는 전역 순서, 멤버는 카테고리 내 순서
- 최초 실행 시 카테고리 "1학년"/"2학년"/"3학년"을 시드하고, 환경변수 `ADMIN_PASSWORD`로 관리자 해시를 저장한다

## 6. 인증

계정과 세션이 없다. **모든 쓰기 요청에 비밀번호를 헤더로 동봉**하고 서버가 매번 해시를 대조한다.

```
X-Member-Id:       12          # 본인 자격으로 요청할 때
X-Member-Password: 1234
X-Admin-Password:  ****        # 관리자 자격으로 요청할 때
```

서버는 요청마다 행위자를 판정한다:

```python
Actor = Admin | Member(id) | Anonymous
```

관리자 헤더가 있으면 우선 관리자로, 없으면 멤버 헤더로 판정한다. 헤더가 있는데 비밀번호가 틀리면 `401`을 반환하고 익명으로 강등하지 않는다.

프론트는 **비밀번호를 저장하지 않는다.** 수정 버튼을 누를 때마다 물어보고, 수정하는 동안만 메모리에 들고 있다가 "완료"를 누르면 버린다. 새로고침해도 남지 않으므로 동아리방 공용 PC에 켜 둔 화면으로 남의 시간표를 고칠 수 없다.

### 비밀번호 보호

- 저장은 bcrypt 해시. 평문은 어디에도 남기지 않는다
- 4자리 숫자는 경우의 수가 10,000개뿐이라 무차별 대입에 취약하다 → **(클라이언트 IP, 대상) 조합으로 실패 10회 시 10분 잠금**
- 실패 카운터는 프로세스 메모리에 둔다. 재시작하면 초기화되지만 그 정도로 충분하다. 이 때문에 **uvicorn 워커는 1개로 배포**한다
- bcrypt 검증 자체가 100ms 안팎이라 초당 시도 횟수에도 자연스러운 상한이 걸린다

## 7. 권한

| 동작 | 익명 | 본인 | 관리자 |
|---|:---:|:---:|:---:|
| 시간표 조회 | ○ | ○ | ○ |
| 멤버 등록 (본인 비번 설정) | ○ | ○ | ○ |
| 본인 일정 추가/수정/삭제 | ✕ | ○ | ○ |
| 타인 일정 추가/수정/삭제 | ✕ | ✕ | ○ |
| 본인 이름 변경 / 삭제 / 비번 변경 | ✕ | ○ | ○ |
| 타인 이름 변경 / 삭제 / 비번 변경 | ✕ | ✕ | ○ |
| 멤버 카테고리 이동 / 이름 순서 드래그 | ✕ | ✕ | ○ |
| 카테고리 추가·수정·삭제·순서 변경 | ✕ | ✕ | ○ |

**표의 배치를 바꾸는 조작은 모두 관리자 전용이다** — 카테고리 CRUD와 순서, 멤버의 소속 이동, 이름 순서 드래그. 한 사람이 순서를 바꾸면 다른 사람의 자리까지 함께 밀리므로, 실수로 표가 헝클어지는 것을 막는다.

본인 자격으로 할 수 있는 것은 자기 일정 추가·수정·삭제, 자기 이름 변경, 자기 비밀번호 변경, 자기 계정 삭제뿐이다.

## 8. API

모든 응답은 JSON. 오류는 `{ "detail": "사람이 읽을 메시지" }` 형태.

### 조회

```
GET /api/board
→ {
    categories: [{ id, name, sort_order }],
    members:    [{ id, name, category_id, sort_order }],
    schedules:  [{ id, member_id, day_of_week, start_slot, end_slot, title, color }]
  }
```

전체 데이터를 한 번에 내려준다. 동아리 규모(수십 명 × 수십 개 일정)에서 페이지네이션은 불필요하다. `password_hash`는 절대 응답에 포함하지 않는다.

### 인증 확인

```
POST /api/auth/verify
body: { scope: "admin" } | { scope: "member", member_id: int }
→ 200 { ok: true } | 401 { detail, locked_until? }
```

프론트의 잠금 해제 UI 전용. 쓰기 요청은 이것과 무관하게 매번 헤더로 검증된다.

### 카테고리 — 관리자 전용

```
POST   /api/categories            { name }
PATCH  /api/categories/{id}       { name }
DELETE /api/categories/{id}
PUT    /api/categories/order      { ordered_ids: [int] }
```

- 소속 멤버가 있는 카테고리 삭제는 `409` + "먼저 소속 멤버를 옮겨 주세요"
- 마지막 남은 카테고리는 삭제할 수 없다 (`409`). 카테고리가 0개가 되면 멤버를 등록할 수 없기 때문
- 이름 중복은 `409`

### 멤버

```
POST   /api/members       { name, category_id, password }   [익명 허용]
PATCH  /api/members/{id}  { name?, password? }               [본인|관리자]
PATCH  /api/members/{id}  { category_id }                    [관리자 전용]
DELETE /api/members/{id}                                     [본인|관리자]
PUT    /api/members/order { category_id, ordered_ids }       [관리자 전용]
```

`PATCH`는 엔드포인트 하나이고, **필드별로 권한을 따로 검사**한다. 본인이 `category_id`를 함께 보내면 그 필드 때문에 `403`으로 거부한다.

- `password`는 정확히 4자리 숫자(`^\d{4}$`)여야 한다. 아니면 `422`
- 이름 중복은 `409`
- 멤버 삭제 시 해당 일정도 함께 삭제된다 (CASCADE)
- `PUT /order`의 `ordered_ids`는 해당 카테고리의 전체 멤버 id 집합과 일치해야 한다. 불일치는 `400`

### 일정

```
POST   /api/schedules       { member_id, day_of_week, start_slot, end_slot, title, color }
PATCH  /api/schedules/{id}  { day_of_week?, start_slot?, end_slot?, title?, color? }
DELETE /api/schedules/{id}
```

모두 `[본인|관리자]`. `member_id`가 대상이며, 본인 자격이면 `X-Member-Id`와 일치해야 한다.

- 같은 멤버·같은 요일에서 시간 구간이 겹치면 `409` + 겹친 일정의 제목과 시간을 메시지에 담는다
- 수정 시 겹침 검사에서 자기 자신은 제외한다
- `title`은 1~30자, `color`는 파스텔 프리셋 10색 중 하나의 hex 값. 목록에 없는 값은 `422`. 팔레트가 바뀌면 `LEGACY_COLORS` 표로 기존 일정 색을 옮긴다

## 9. 프론트엔드

### 구성

```
frontend/src/
  api/client.ts             fetch 래퍼. 인증 헤더 자동 부착, 오류 → 예외 변환
  utils/timeSlot.ts         슬롯 ↔ "HH:MM" 변환, 겹침 판정
  stores/board.ts           Pinia. 서버 데이터 + 선택 상태 + 잠금 상태
  components/
    MemberPanel.vue         카테고리별 멤버 목록, 다중선택 체크박스, 드래그 재배치
    CategoryEditor.vue      관리자용 카테고리 CRUD
    MemberDialog.vue        이름 등록/수정/비번 변경
    ScheduleGrid.vue        격자 렌더링
    MyScheduleList.vue      내 일정 텍스트 목록 + 추가/수정/삭제 진입
    ScheduleDialog.vue      일정 추가/수정 폼
    UnlockDialog.vue        비밀번호 입력 (본인/관리자)
  App.vue                   레이아웃 셸
```

각 파일이 한 가지 일만 한다. `ScheduleGrid`는 그리는 것만, `timeSlot.ts`는 변환만, `client.ts`는 통신만 책임진다. 내부를 바꿔도 다른 파일이 깨지지 않는다.

### 화면

```
┌─ 상단 바 ────────────────────────────────────────────────┐
│  [카테고리 관리]  [이름 등록]  [내 일정]  [관리자 모드]    │
├─ 멤버 패널 ──────────────────────────────────────────────┤
│  1학년   ☑철수  ☑영희  ☑민수      ← 클릭으로 다중선택     │
│  2학년   ☐지훈  ☑수빈             ← 관리자 모드에서만     │
│                                      드래그로 순서/소속 변경│
├─ 시간표 ─────────────────────────────────────────────────┤
│         │      월      │      화      │   ... 가로 스크롤 →│
│  시간   │철수│영희│민수│철수│영희│민수│                    │
│  09:00  │수업│    │알바│    │강의│    │                    │
│  09:30  │ ↕  │    │ ↕  │    │ ↕  │수업│   ← 세로 36행       │
│  10:00  │    │강의│ ↕  │    │    │ ↕  │                    │
└──────────────────────────────────────────────────────────┘
```

관리자 모드가 아닐 때 멤버 패널의 드래그 핸들은 아예 나타나지 않는다.

### 격자 렌더링

CSS Grid 하나로 그린다.

```
grid-template-columns: [시간축] repeat(7 × 선택인원, 1fr)
grid-template-rows:    [요일헤더] [이름헤더] repeat(36, 22px)
```

세로는 화면 높이에 맞춰 36행을 `1fr` 로 균등 분배한다. 스크롤 없이 06:00부터 24:00까지 통째로 보인다.

가로도 스크롤을 두지 않는다. 대신 **요일 단위 페이지**로 나눈다. 남은 폭에 요일이 몇 개 들어가는지 재서, 다 들어가면 한 페이지, 아니면 이레를 고르게 갈라 넘긴다(세 개씩 들어가면 3·2·2, 네 개씩이면 4·3). 페이지는 **잡아끌거나 좌우 방향키**로 넘기고, 격자 아래 화살표와 점으로 어디쯤인지 알린다.

좁은 화면(860px 이하)은 예외다. 서른여섯 줄을 다 욱여넣으면 한 줄이 8px 남짓이라 읽을 수 없으므로, 줄 높이를 지키고 세로로 스크롤한다.

선택된 사람이 없으면 격자 대신 "이름을 선택해 주세요" 안내를 띄운다.

### 일정 블록 표시

**한 일정은 몇 칸에 걸치든 블록 하나로 그리고, 제목은 그 안에 한 번만 쓴다.**

`grid-row: (start_slot + 3) / (end_slot + 3)`으로 배치하므로 09:00~13:00짜리 4시간 일정은 8칸을 차지하는 **세로로 긴 블록 하나**가 되고, 그 안에 제목이 한 번 들어간다. 30분 칸마다 제목이 반복되는 일은 없다.

블록 안에 담기는 것은 **제목 텍스트뿐**이다. 시간, 아이콘, 요일 표기 같은 부가 정보는 넣지 않는다.

- 제목은 블록 세로 가운데 정렬, 열 폭에 맞춰 줄바꿈
- 블록 높이보다 길면 말줄임(…)
- 마우스를 올리면 `월 09:00~13:00 전공수업` 형태의 툴팁으로 전체 내용 표시

### 내 일정 관리 — 텍스트 목록

상단 "내 일정" 버튼을 누르면 잠금 해제한 본인(관리자면 고른 멤버)의 일정이 **요일·시간순 텍스트 줄**로 나열된다. 격자를 클릭하지 않고 여기서 전부 관리할 수 있다.

```
월  09:00 ~ 13:00   전공수업          [수정] [삭제]
화  13:00 ~ 17:00   알바              [수정] [삭제]
목  10:00 ~ 11:30   교양강의          [수정] [삭제]

                                      [+ 일정 추가]
```

한 줄이 곧 "무슨 요일 몇 시부터 몇 시까지 무슨 일정"이라는 문장이다. 그 이상의 정보는 표시하지 않는다.

### 일정 추가/수정 폼

| 필드 | 입력 |
|---|---|
| 대상 | 본인 자격이면 본인 고정, 관리자면 멤버 선택 |
| 요일 | 월~일 선택 |
| 시작 / 종료 | 30분 단위 드롭다운 (06:00~24:00) |
| 제목 | 텍스트 (1~30자) |
| 색상 | 프리셋 팔레트 10색 |

격자에서 일정 블록을 클릭해도 같은 폼이 수정 모드로 열린다. 편집 권한이 없으면 읽기 전용으로 뜬다.

### 상태 유지

`localStorage`에 남기는 것은 **선택한 멤버 id 목록**뿐이다. 다시 열면 보고 있던 사람들이 그대로 뜨지만, 고치려면 비밀번호를 다시 넣어야 한다. 관리자 비밀번호도 저장하지 않으므로 새로고침하면 관리자 모드가 풀린다.

### 동기화

여러 명이 동시에 편집하므로 **15초 간격 폴링**으로 `GET /api/board`를 다시 불러온다. 탭이 백그라운드일 때(`document.visibilityState !== 'visible'`)는 건너뛰고, 포커스가 돌아오면 즉시 한 번 갱신한다. 모달이 열려 있는 동안에는 입력 중인 내용이 날아가지 않도록 화면 반영을 미룬다.

## 10. 에러 처리

| 상황 | 응답 | 화면 |
|---|---|---|
| 비밀번호 불일치 | 401 | "비밀번호가 틀렸습니다 (남은 시도 N회)" |

| 일정 시간 겹침 | 409 | "월요일 09:00~10:30 '전공수업'과 겹칩니다" |
| 소속 멤버 있는 카테고리 삭제 | 409 | "소속된 멤버 3명을 먼저 옮겨 주세요" |
| 마지막 카테고리 삭제 | 409 | "카테고리는 최소 1개 있어야 합니다" |

| 네트워크 실패 | — | 상단 배너 "서버에 연결할 수 없습니다. 재시도 중…" |

## 11. 테스트

### 백엔드 (pytest)

- `test_auth.py` — 비밀번호 검증, 행위자 판정 우선순위, 실패 10회 후 잠금, 잠금 해제
- `test_permissions.py` — 권한 매트릭스 전수: (익명 / 본인 / 타인 / 관리자) × (일정 CRUD, 이름·비번 변경, 계정 삭제, 카테고리 이동, 순서 변경, 카테고리 CRUD). 특히 **본인이 `category_id` 변경과 순서 변경을 시도하면 403**인지 확인
- `test_schedules.py` — 겹침 거부, 인접(끝=시작) 허용, 수정 시 자기 제외, 슬롯 범위 검증
- `test_members.py` — 비번 형식, 이름 중복, 삭제 시 일정 CASCADE, 순서 배열 검증
- `test_categories.py` — 소속 멤버 있을 때 삭제 거부, 마지막 카테고리 삭제 거부, 순서 변경
- 각 테스트는 임시 SQLite 파일에서 독립 실행

### 프론트엔드 (Vitest)

- `timeSlot.spec.ts` — 슬롯 ↔ 시간 변환 왕복, 경계값(0=06:00, 36=24:00)
- `board.spec.ts` — 선택 상태, 잠금 상태, 격자 열 구성 계산, **일정 블록의 grid-row 범위 계산**(여러 칸 일정이 블록 하나로 병합되는지)

## 12. 배포

멀티스테이지 Dockerfile:

1. `node` 스테이지에서 `npm run build` → `dist/`
2. `python` 스테이지에 `dist/`를 복사, FastAPI가 `StaticFiles`로 서빙

환경변수:

| 변수 | 기본값 | 설명 |
|---|---|---|
| `ADMIN_PASSWORD` | (필수) | 최초 실행 시 해시로 저장. 멤버 비번과 달리 4자리 제한이 없는 자유 문자열 (8자 이상 권장) |
| `DB_PATH` | `./data/schedule.db` | SQLite 파일 경로 |

SQLite 파일이 든 디렉터리만 볼륨으로 마운트하면 데이터가 유지된다. uvicorn 워커는 1개 (6장 참조).

## 13. 구현 순서

1. 백엔드 스켈레톤 + 스키마 + 시드 + `GET /api/board`
2. 인증 모듈 (해시, 행위자 판정, 시도 제한) + 테스트
3. 멤버·카테고리 API + 필드별 권한 + 테스트
4. 일정 API + 겹침 검증 + 테스트
5. 프론트 스켈레톤 + API 클라이언트 + 스토어
6. `ScheduleGrid` 렌더링 (읽기 전용, 블록 병합 포함)
7. 멤버 패널: 선택, 잠금 해제, 이름 등록
8. `MyScheduleList` 텍스트 목록 + 일정 추가/수정/삭제 폼
9. 카테고리 관리 + 관리자 전용 드래그 재배치
10. 폴링 동기화, 에러 배너, Dockerfile
