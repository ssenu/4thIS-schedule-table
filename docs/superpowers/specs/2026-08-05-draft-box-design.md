# 초안 상자 — 그린 뒤 다듬고 나서 폼 열기

## 무엇을 바꾸는가

수정 모드에서 격자를 끌어 새 일정을 그릴 때, 지금은 **손을 떼는 순간 폼이 뜨고
초안이 사라진다**. 시간을 잘못 잡았으면 폼을 닫고 처음부터 다시 끌어야 한다.

손을 떼도 초안이 그 자리에 남게 한다. 남아 있는 동안 길이를 고치거나 다른
요일로 옮기고, 다 됐을 때 **⊕** 를 눌러 폼을 연다.

## 초안의 상태

```
없음  ──끌기──▶  그리는 중  ──손 뗌──▶  놓임  ──⊕──▶  폼
                                        │
                                        ├──끝을 잡고 끌기──▶ 길이 바꾸는 중
                                        └──가운데를 잡고 끌기──▶ 옮기는 중
                                                                  │
                                        ◀──손 뗌───────────────────┘
```

"놓임" 이 이번에 새로 생기는 상태다. 나머지 흐름은 그대로다.

## 조작

| 어디를 잡는가 | 무슨 일이 일어나는가 |
|---|---|
| 빈 칸 | 새 초안을 그린다. 이미 있던 초안은 대체된다 |
| 초안의 **위쪽 끝** | 시작 시간이 바뀐다. 끝 시간은 그대로 |
| 초안의 **아래쪽 끝** | 끝 시간이 바뀐다. 시작 시간은 그대로 |
| 초안의 **가운데** | 길이를 유지한 채 옮긴다. 다른 요일로도 간다 |
| **⊕** | 지금과 같은 일정 폼이 열린다 |

끝으로 치는 영역은 마우스 12px, 손가락 16px(`pointer: coarse`). 손가락으로
가장자리를 집기 어려운 것을 감안한다.

### 규칙

- 최소 길이는 **30분**(1슬롯). 위 끝을 아래로 밀어도 30분은 남는다.
- 격자 밖으로 나가지 않는다. 슬롯 0(06:00)~36(24:00) 안에 머문다.
- 옮길 때 길이는 변하지 않는다. 아래쪽 경계에 닿으면 거기서 멈춘다.
- **요일만 바뀐다.** 남의 열로는 옮길 수 없다 — 본인 열에서만 그린다는 기존
  규칙 그대로다.

## 초안이 사라지는 경우

- 격자의 빈 곳을 **끌지 않고 누르기만** 했을 때
- 다른 자리에서 새로 끌기 시작했을 때 (이전 초안을 대체)
- **ESC** 를 눌렀을 때
- 폼에서 저장하거나 취소했을 때
- 수정 모드를 나갔을 때

## ⊕ 버튼

초안 오른쪽 바깥, 세로 가운데에 띄운다. 초안이 짧든 길든 같은 자리라 찾기 쉽고
블록을 가리지 않는다.

**맨 오른쪽 열(그 화면의 마지막 요일)에서는 왼쪽에 붙인다.** 그대로 두면 화면
밖으로 밀려 누를 수 없다.

## 코드

`ScheduleGrid.vue` 는 이미 710줄이다. 경계·최소 길이·요일 넘나들기 규칙까지
넣으면 더 불어나고, 브라우저를 띄우지 않고는 검증할 수 없게 된다.

규칙만 **`utils/draftBox.ts`** 로 떼어 순수 함수로 둔다. 격자 배치를
`gridLayout.ts` 로 뺀 것과 같은 방식이다.

```ts
interface DraftBox {
  day: number
  start: number  // 0..35, 포함
  end: number    // 1..36, 배타
}

fromDrag(day, anchor, cursor): DraftBox   // 처음 그릴 때
resizeStart(box, slot): DraftBox          // 위 끝을 옮긴다
resizeEnd(box, slot): DraftBox            // 아래 끝을 옮긴다
moveTo(box, day, topSlot): DraftBox       // 통째로 옮긴다
```

`ScheduleGrid.vue` 는 포인터 이벤트를 받아 이 함수들을 부르고 결과를 그린다.

### 좌표에서 열 찾기

요일을 넘나들려면 포인터가 지금 어느 열 위에 있는지 알아야 하는데, 포인터를
붙잡아 둔(`setPointerCapture`) 동안에는 `event.currentTarget` 이 처음 열에
묶여 바뀌지 않는다.

각 열(`.lane`)에 `data-day` 와 `data-member` 를 달고,
`document.elementsFromPoint(x, y)` 로 좌표 아래의 열을 찾는다. 본인 열이 아니면
무시한다.

## 겹치면 빨갛게

이미 있는 일정과 자리가 겹치면 초안이 **빨간 점선**으로 바뀌고 ⊕ 가 잠긴다.
누르려 하면 "이미 있는 일정과 겹칩니다" 라고 알린다.

바탕은 반투명으로 둔다. 불투명하면 **무엇과 부딪혔는지** 아래 블록이 가려
보이지 않는다.

판정은 `clashes()` 로 서버와 같은 규칙을 쓴다 — 끝나는 칸과 시작하는 칸이
맞닿는 것은 겹침이 아니다. 11:00 에 끝나는 수업과 11:00 에 시작하는 알바는
나란히 있을 수 있다.

## 있던 일정도 잡아 옮긴다

수정 모드에서는 **이미 만들어 둔 블록도 잡아서** 다른 요일·시간으로 옮긴다.
잡으면 초안과 같은 점선 상자가 따라다니고, 원래 자리는 흐려져 어디서
떠나왔는지 남는다.

**Ctrl(맥은 Cmd)을 누른 채 옮기면 원본을 두고 하나 더 만든다.** 제목과 색은
원본 그대로다. 복사 중에는 상자가 실선으로 바뀌고 "· 복사" 가 붙는다. 끄는
도중에 눌렀다 떼도 되도록, 손을 뗄 때의 상태로 판단한다.

옮긴 자리는 **폼 없이 곧바로 저장된다.** 이미 있는 일정을 옮기는 것이고,
마음에 들지 않으면 다시 잡아 옮기면 된다. 겹치는 자리에 놓으면 저장하지 않고
되돌린 뒤 알린다.

**제자리에서 눌렀다 떼면 옮긴 것이 아니라 누른 것이다** — 예전처럼 편집 폼이
열린다. 자리가 한 칸이라도 달라졌을 때만 옮긴 것으로 본다.

## 범위 밖

옮기는 것은 **요일과 시간까지**다. 남의 열로는 옮길 수 없다 — 일정의 주인을
드래그로 바꾸는 것은 실수하기 쉽고 되돌리기 어렵다.
